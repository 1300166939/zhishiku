# 评测方法、结果与适用范围

本文公开原部署环境的脱敏汇总结果，评测日期为 2026-10-22 与 2026-10-26。原业务语料、问题文本、原始响应、内部链接和凭证不随公开仓库发布，因此第三方不能仅靠本仓库重现这些业务指标。

本仓库的合成测试用于验证实现契约；它与真实语料检索评测、生产性能和业务验收是不同层次。机器、语料、授权范围、模型与供应商状态变化后，需要重新评测。

## 指标定义

| 指标 | 定义 | 不能推出的结论 |
|---|---|---|
| Hit@K / TopK 命中率 | 前 K 条结果中至少有一条属于冻结标签中的目标记录 | 不能证明所有结果相关，也不能证明生成答案正确 |
| Precision@5 / Top5 结果精确率 | 前 5 条中相关记录比例，按题汇总 | 不能证明原文当前有效或规则完整 |
| 项目路径相关性 | 返回来源路径属于题目目标项目的比例，按题宏平均 | 同项目内容也可能不回答问题，不能当业务答案准确率 |
| 必需知识点覆盖 | 目标原文包含预先指定的字段或步骤 | 不验证字段是否仍适用，也不验证 Agent 执行 |
| 引用可追溯 | 摘录可在所绑定的返回原文中定位 | 不证明源文档事实正确 |
| 负例拒答率 | 无答案测试中正确拒答的比例 | 小样本结果不能证明所有未知主体均能可靠拒答 |
| HTTP 成功率 | 请求获得预期 HTTP 成功响应的比例 | HTTP 200 不等于答案质量通过 |
| P50 / P95 | 请求延迟的中位数/第 95 百分位 | 受样本与并发条件限制，不能直接当生产 SLA |

## 一、API 混合检索与重排试点（2026-10-22）

### 方法

冻结 62 题：54 个正例、4 个无记录过滤问题、4 个语义无答案问题。54 个正例覆盖 38 个意图，部分为成对改写，不能当作 54 个独立业务意图。

标签由已迁入语料构建，在检索前冻结，未经业务负责人独立标注。依据原记录 ID 和指定原文知识点判断相关性；不使用模型自评分，不用目标 source_id 限定答案。

同候选对照捕获实际 BM25/Exact/Dense → RRF 候选，比较 RRF 排序与 RRF 加重排的输出，没有修改生产开关或另造一批候选。随后使用 HTTPS 验证真实接口。该方法隔离了“同候选重排”的影响，但不代表跨语料或全项目泛化能力。

### 质量结果

| 指标 | 同候选 RRF | RRF + qwen3-rerank | 变化 |
|---|---:|---:|---:|
| Top1 命中率 | 74.07% | 90.74%（49/54） | +16.67 个百分点 |
| Top5 命中率 | 90.74% | 92.59%（50/54） | +1.85 个百分点 |
| Top10 命中率 | 96.30% | 98.15%（53/54） | +1.85 个百分点 |
| Top20 命中率 | 98.15% | 98.15%（53/54） | 不变 |
| Top5 结果精确率 | 51.48% | 54.44% | +2.96 个百分点 |
| Top5 必需知识点覆盖率 | 90.74% | 92.59% | +1.85 个百分点 |
| Top5 相关原记录集合召回率 | 62.99% | 64.36% | +1.37 个百分点 |
| MRR@20 | 0.8279 | 0.9247 | +0.0968 |
| nDCG@5 | 0.8022 | 0.8831 | +0.0809 |

Top5 命中率 92.59% 表示多数问题能找到至少一条目标记录。Top5 精确率 54.44% 表示按冻结标签计算，前 5 条平均约 2.72 条相关。二者不能互换。

重排使 12 题 Top1 改善、3 题退步，净增 9 题。54 个正例全部实际应用重排，没有降级。有的精确参数名与执行链顺序问题出现排序退步。

4 个无记录过滤问题均正确返回空；4 个语义无答案问题均未可靠拒答。旧检索接口返回候选，不具备可靠的通用语义拒答阈值。

### 性能结果

| 场景 | HTTP 样本数 | 成功 | P50 | P95 | 最大 |
|---|---:|---:|---:|---:|---:|
| 单请求、top_k=5 | 40 | 40/40 | 0.981 秒 | 1.358 秒 | 2.013 秒 |
| 双并发、top_k=5 | 40 | 40/40 | 1.185 秒 | 2.030 秒 | 3.108 秒 |
| 批量 4 任务 | 6 批 | 6/6 | 3.164 秒 | 3.297 秒 | 3.297 秒 |

本轮共 151 次 HTTP（准确率 62、预热 3、单请求 40、双并发 40、批量 6）均成功，无超时。预热不计入正式性能分位数。P95 使用 nearest-rank，即排序后的第 ceil(0.95 × n) 项。

HTTPS 延迟包含工作站网络、TLS、网关、向量与重排供应商调用。批量任务在一个查询槽内顺序执行，整批延迟不能除以 4 当作并发单题延迟。以上是限定场景小样本，未证明持续吞吐或 SLA。

## 二、公共证据路径配对评测（2026-10-26）

### 方法

冻结 10 题：6 个正例、4 个不存在主体/模块的负例。最初 6 题用于回归，补充 4 题在主体门槛修复后冻结且未用于调参；这仍是同业务域小样本，不是独立业务 gold。

每题先 `/search` 后 `/ask`，各请求一次，均 top_k=5。旧路径使用混合召回及条件重排；新路径使用词法 FTS、主体检查和邻接章节，不调用 Embedding、向量、重排或生成模型。两者上下文预算不同，关联章节可使新路径引用数超过 5。

项目路径相关性只检查来源是否属于目标项目；功能清单命中只检查资料类型。它们不验证业务规则完整性与有效版本。超时保留为失败，不用后续重试替换。

### 配对结果

| 指标 | `/search` | `/ask` |
|---|---:|---:|
| HTTP 成功率 | 90%（9/10） | 90%（9/10） |
| 客户端超时 | 1 次 | 1 次 |
| 成功请求耗时中位数 | 6.851 秒 | 0.331 秒 |
| 成功请求最大耗时 | 22.731 秒 | 0.510 秒 |
| 成功正例项目路径相关性宏平均 | 78.33%（5 题） | 100%（5 题） |
| 核心功能问题命中功能清单 | 50%（1/2） | 100%（2/2） |
| 负例拒答率 | 0%（0/4） | 100%（4/4） |

新路径 32 条摘录均能绑定并定位到返回原文：30 条为完整行匹配、2 条为 1500 字符上限产生的截断前缀。引用定位率为 32/32，但不是答案事实正确率。

这两条路径的算法与预算不同，不能把延迟差计算为“同算法加速倍数”，也不能与 2026-10-22 的 API 性能分布混合。新路径 100% 项目路径相关性不能替代 API Top5 精确率 54.44%。

### 失败与边界

两条路径各保留一次 35 秒客户端读取超时。某次 `/ask` 的服务端检索阶段约 155ms 完成，仍不能确证客户端、网络、响应前授权或其他链路的根因。独立诊断重试成功，但未覆盖原失败样本。

10 题不足以建立 P95/P99、长期容量或 SLA。另有 API `/ask` 0.601 秒、App `/ask` 2.494 秒的单次 smoke，仅证明当次授权查询可用，不能推广为专属库普遍时延。

## 三、实现与安全验证

| 验证层次 | 结果 | 覆盖范围 |
|---|---|---|
| 原部署架构定向回归 | 64 项通过；后续 16/13 项定向通过 | 集合重叠，不累加为独立样本 |
| 真实 HTTPS 权限检查 | 7/7 符合预期 | 公共/专属、域/项目越权及正常访问；不等于全部组织身份场景 |
| 数据与索引完整性 | 3 库 SQLite integrity 正常、FTS 缺项 0 | 原业务记录与策略摘要保持 |
| 隔离恢复 | 2 个真实来源版本、2 条 2048 维文本向量恢复/查询通过 | 临时空间已清理，非全量或离站灾备 |
| 公开代码本地验证 | 124 服务测试 + 5 模型接入测试通过 | 合成夹具、模拟模型/存储；不含私有业务报告 |
| 公开代码 GitHub CI | 代码与上一版中文文档提交的 Linux 检查通过 | 新提交的运行状态以 GitHub Actions 为准 |
| 发布前脱敏检查 | 公开扫描、已知私值比对与 Gitleaks 无发现 | 原业务问题、响应、数据库和私有配置不公开 |

## 四、下一轮评测要求

1. 由业务负责人独立确认权威来源、有效版本、替代关系和标准答案。
2. 将开发调参题集与验收留出题集分开，确定正式阈值。
3. 覆盖同义改写、精确参数、完整规则、版本冲突、无答案、权限拒绝、图文派生与跨资料问题。
4. 分别报告 Hit@K、Precision@K、知识点覆盖、引用定位、拒答、错误拒答、延迟和错误率。
5. 保留失败和超时，重试单列；按域、项目、问题类型、模型与并发条件分组。
6. 补充宽 App/混合并发/持续负载，以及全量与离站恢复；当前不发布生产 SLA 或业务答案准确率保证。
